# 2026-08-30

## 修复：双击 uragan.cmd 闪退 + `uragan tui` 卡在「正在启动…」

### 根因
1. **TUI 死锁**：`packages/cli/src/tui/app.tsx` 的 `openProject()` 在打不开工程时执行
   `setState((s) => (s ? {...s, toast} : s))` —— 启动时 `state` 本就是 `undefined`，这条分支什么都不做，
   `state` 永远是 `undefined`，界面永久停在「正在启动…」。触发条件：`project.uragan` 不在当前目录。
2. **双击闪退**：commander 未收到子命令时打印 help 并 `exit(0)`，双击拉起的控制台窗口随即关闭。

### 改动
- `state.ts`：新增 `UNOPENED_ID` / `emptySnapshot()` / `isUnopened()`，给出「空载态」这一档状态。
- `app.tsx`：`openProject` 失败时落到 `emptySnapshot(...)`（toast 提示「按 N 新建 / O 打开」）；
  `useEffect` 加 try/catch 兜底；`closeProject` 复用 `emptySnapshot`；头部在空载态显示引导文案。
- `index.ts`：新增根 `program.action(...)` —— 无子命令 + 交互终端 → 直接进 TUI，非交互 → 打印帮助，
  带未知操作数 → 报错。新增 `ensureWorkspace()`：未显式给 `-p` 且 cwd 位于安装目录内时切到
  `%USERPROFILE%\Documents\UraGAN`（`URAGAN_WORKDIR` 可覆盖），避免工程被建进 `build/uragan`（下次打包会被清空）。
- `scripts/package-portable.mjs`：`wrapCmd` 重写 —— 双击检测（CMDCMDLINE 含 /c 且含脚本名）、
  node 缺失提示、**仅在「双击且无参数」且失败时 pause**（脚本里带子命令失败不能卡住）。
  新增 `--bin-only`（只重建 bin 入口，跳过 270MB vendor 拷贝）。
- 新增回归测试 `packages/cli/test/tui-startup.test.ts`：用假 stdin/stdout 渲染 ink，
  断言工程不存在时不再出现「正在启动」。已验证：改回旧代码该测试会失败。

### 踩坑
- **`pnpm pack` 是 pnpm 内置命令**，会盖住 package.json 里的同名脚本，必须用 `pnpm run pack`
  （踩过一次：误生成 27MB 的 `uragan-0.1.0.tgz`）。README 已统一改成 `pnpm run pack`。
- 打包脚本里的 `rm(OUT, {recursive:true})` 会触发环境的批量删除保护（>50 文件），
  重跑前需先用 PowerShell `Remove-Item -Recurse -Force` 清掉 `build/uragan`。
- vitest 里渲染 ink 需要假 stdin 具备 `isTTY/setRawMode/ref/unref`，用 `PassThrough` + 补 `ref/unref` 可行。
- `packages/mcp` 的 2 个测试在 `pnpm -r test`（并行）下会因 5s 超时失败，单跑通过 —— 与本次改动无关。

### 事故（已修复）
验证 mcp 是否为既有失败时用了 `git stash push`，该操作触发的 repack 中断，
导致 `.git/refs` 目录丢失、`.git/objects/pack/*.pack` 被删（只剩 .idx）。
恢复方式：按 packed-refs/reflog 重建 `refs/heads/main`（真实 SHA 取自 `.git/logs/refs/heads/main`：0b0f537）、
`refs/heads/agents/...`、`refs/remotes/origin/main`，移走孤立 .idx 与 commit-graph，再 `git fetch origin`
把对象取回；`git fsck` 已干净。两个 IDE agent 检查点 ref（0dbe80d/93e2a45）不在远端，无法恢复。
**教训：不要在这个仓库里用 `git stash`；需要验证基线时改用拷贝文件或 `git worktree`。**

## 修复：TUI 打开 legacy 单文件工程崩溃（EEXIST）

用户报错：`EEXIST: file already exists, mkdir 'D:\下载\新建文件夹 (13)\win11-promo.uragan'`，
栈：`engine.openProject → writeProjectDir → mkdirSync`，从 `use-input` 冒出 → 整个进程崩。

### 根因
`projectDirFor('win11-promo.uragan')` 去掉扩展名再加 `.uragan` → **和源文件同名**。
`writeProjectDir` 要在这个路径建目录，而那里已经是个文件 → EEXIST。
`store.ts` 原注释「含同名 legacy 单文件时目录与文件可共存」是错的：文件与目录不可能同名。
再加上 TUI 的 `useInput` 里 `openProject` 没有异常保护，异常直接冒到 ink 的输入回调 → 进程退出。

### 改动（三层防御）
1. `core/store.ts`：新增 `isExistingFile()`；`writeProjectFile` 改为**形态由磁盘现状决定** ——
   已是目录 → 拆分写；已存在且是文件 → 单文件写（保持 legacy）；不存在且 .uragan → 目录形态。
2. `core/engine.ts`：`openProject` 中目标目录名被同名文件占用时**就地以单文件形态打开**
   （`converted:false` + U-9013 warning）；`writeProjectDir` 包 try/catch，落盘失败转成 report 错误，不再抛出。
3. `cli/app.tsx`：`openProject` 内 try/catch；`useInput` 再包一层全局兜底 ——
   任何一次按键里的 IO 异常只变成底部 toast，**TUI 不再因一次操作整体崩溃**（`exportSkeletons` 之类本来也没保护）。

### 测试
- `packages/core/test/core.test.ts` +4：legacy 打开/保存保持单文件、新工程仍是目录、落盘失败不抛出。
- `packages/cli/test/tui-startup.test.ts` +1：向假 stdin 注入 `o`、`\r` 模拟文件管理器回车打开 legacy 文件，断言无 EEXIST/ERROR。
- 两条都验证过能抓到旧 bug（临时改回旧逻辑 → 报出完全相同的 EEXIST）。

### 环境注意
`build/uragan` 太大，回收站删不掉（PowerShell `Remove-Item` / node `fs.rm` / `fs.cp` 覆盖 都被 safe-delete 拦截）。
依赖没变时只需同步 dist：`readFileSync/writeFileSync` 逐文件覆盖（避开 shim），132 个文件。
完整重打包得先让 `build/uragan` 不存在（目录较小时 PowerShell 能删掉）。

## 需求落地：.uragan = 持久文件，工程在 .uragan.work 工作目录中进行

用户定下的模型（我上一版「legacy 单文件就地打开、不展开」被推翻）：
```
win11-promo.uragan          文件 · 持久存储（原文件）
win11-promo.uragan.work\    目录 · 工程实际在这里进行
```
打开 = 导入（拆页写入工作目录，原文件原样保留）；编辑实时进工作目录；
**保存（Ctrl+S）= 导出回原 .uragan**；不保存也能渲染/校验（都读工作目录）；
再次打开复用工作目录（未导出的改动不能被重新导入覆盖）。
用户选定：目录后缀 `.work`（即 `<源名>.uragan.work`）、保存键只用 Ctrl+S、`.json/.jsonc` 维持原状不带持久文件。

### 改动
- `shared/constants.ts`：新增 `WORK_DIR_SUFFIX = '.work'`。
- `core/store.ts`：新增 `workingDirFor() / isWorkingDirName() / isDurableSource()`。
- `core/engine.ts`：`OpenResult` 新增 `durablePath?`；`openProject` 对 `.uragan` 单文件走
  「导入 → `<源名>.uragan.work`」，工作目录已存在则直接复用（converted=false）；落盘失败仍转 report 不抛出。
- `cli/tui/state.ts`：`TuiSnapshot` 新增 `durablePath?` 与 `dirty`；`snapshot()` 第三参；
  `isOpenableProject/isOpenableDir` 认识 `.uragan.work` 目录。
- `cli/tui/app.tsx`：`save()` 落工作目录并置 dirty；新增 `saveDurable()`（Ctrl+S，以工作目录为准回写）；
  头部显示 `● 未保存（Ctrl+S → 原文件）` / `✓ 已同步 原文件`；Q 在有未保存改动时需按两次；
  快捷键表加入 Ctrl+S。

### 顺手修掉的既有 bug
字段编辑态排在全局动作键**之后**，导致 `s/i/r/e/o/n/m/u/x/q` 这些字母在编辑字段值时
会被当成快捷键吃掉（X 直接关掉工程），根本打不进内容。已把 `s.sub === 'edit'` 分支提到全局动作键之前。
写测试时才撞出来，说明这条路径此前没人测过。

### 收尾补的两处（第二轮）
1. **`projectDir()` 语义**：有持久文件时改为返回**原 .uragan 所在目录**，不是工作目录。
   否则用户原本放在 .uragan 旁的 `assets/` 会突然找不到，render.mp4 / skeleton.json 也跑进 `.work` 里。
   工作目录只负责放按页拆分的文件，是内部区。已加测试（按 S 导出骨架，断言落在原文件旁）。
2. **`.gitignore`**：`*.uragan` 匹配不到 `*.uragan.work` 目录，会混进版本库，已加 `*.uragan.work/`。

### 测试（core 39 / cli 25 全过）
- core：整体工程与独立页面都派生工作目录、改动实时进目录而原文件不动、Ctrl+S 回写后原文件仍是文件、
  再次打开复用（未导出改动不丢）、json 源不带持久文件、落盘失败转 report。
- cli：`.uragan.work` 可被文件管理器识别；TUI 端到端——Tab/Enter 改字段 → 显示未保存 → Ctrl+S 导出回原文件；
  产出物落在原文件旁。
- `pnpm --filter @uragan/mcp test` 单独跑 15/15 通过；在 `pnpm -r test` 下会因首次 import @uragan/render
  超过 5s 默认超时而偶发失败 —— 与本次改动无关的老问题。

## 清理旧设计入口（E / M / U）+ 目录分工定型（第三轮）

用户要求移除 `E 导出整体配置`、`M 导入配置`，并指出 `U 导入单页文件` 重复。
这三者在「持久文件 + 工作目录」模型里都已由别的能力取代：
- 导出整体配置 → Ctrl+S 导出回原 .uragan
- 导入配置 → O 打开工程（任何文件源都是「打开 = 导入」）
- 导入单页 → 把页文件直接放进工程目录，`readProjectDir` 会自动吸收（`absorbForeignPageFile`）

用户选定目录分工（问过一次）：**文案框架 skeleton.* 进工程目录**，
**render.mp4 / 导出单页 / assets 留在原文件旁**。于是把 `projectDir()` 拆成两个：
- `workDir()` = `state.projectPath`（工程本体 + 文案框架）
- `outputDir()` = 有持久文件时 `dirname(durablePath)`，否则工程目录本身（资产、视频、导出单页）

顺带修掉：`I 导入文案` 之前只更新内存态、不置 dirty，导入后头部仍显示「已同步」——
现在走 `save()` 落盘并置 dirty。

改动：`cli/tui/app.tsx`（删 3 个函数 + 键位 + 会话态收窄为 `new | fm`、SHORTCUTS 与两处提示文案、
projectDir 拆分、清掉失效 import）、`cli/test/tui.test.ts`（快捷键断言 + 新增「旧入口已移除」断言）、
`cli/test/tui-startup.test.ts`（skeleton 落点断言翻转）、README（目录分工图 + 已移除入口说明）。
最终 core 39 / cli 26 全过，typecheck 5/5。

**未动**：CLI 的 `uragan export/import` 命令与 MCP 的 `project_export/project_import` 工具仍在

## 第四轮：U 加回（重复的只是按钮）+ CLI/MCP 语义统一

用户纠正：所谓「U 重复」是指**页面视图同一帧里出现了两个一样的 U**
（上下文键位一个 + 全局 SHORTCUTS 一个），功能本身要保留。

### 1. U 加回，只显示一次
`importPageFile()` 恢复；会话态恢复 `new | pageImport | fm`；
渲染时 U 只放在**页面视图的上下文键位**（与 G 配对），**不进 SHORTCUTS**。
测试：`expect(SHORTCUTS.map(s=>s.k)).not.toContain('U')` +
渲染后断言单帧里 `导入单页文件` 只出现 1 次（跨帧累加会翻倍，必须数单帧）。

### 2. CLI / MCP 与 TUI 的打开语义统一（最大的误解源）
原来 CLI（`loadFile`）和 MCP（`load`）都用 `readProjectFile` 直接读 `.uragan` 文件 ——
在持久文件模型下读到的是**可能过期的原文件**，而 TUI 读的是工作目录，两边内容不一致。
现在三者都走 `Uragan.openProject`：
- CLI：`loadProject()` 返回 `OpenResult`；`saveProject(r, file)` 落工程目录 + 有持久文件时导出回原文件
  （CLI 是显式操作，等价于「保存」）
- MCP：`load()` 返回 `OpenResult & { dir }`，`save(r, file)` 同理
- 共用 `outputDirFor(projectPath, durablePath)`（新加到 `core/store.ts`）算产出/资产目录，
  TUI 的 `outputDir()` 也改用它，避免三处各算一套
- 渲染/资产体检的 `projectDir` 从 `dirname(target)` 改为 `assetDir(opened)`

实测：TUI 里改了顺序但未 Ctrl+S → `uragan pages list -p 同一文件` 看得到新顺序 ✓
`uragan pages reorder` → 工作目录与原文件同时更新 ✓

最终：typecheck 5/5，core 40 / cli 28 / mcp 15 全过。

## 第五轮：project_export / project_import 保留，只改描述文案

用户问「少这两工具会怎么样」，查证后给出影响分析，用户选择**都留、只改描述**。

### 查证结论（将来别再靠印象）
- `project_export` 删了 → 失去唯一产出 `$shared` 去重视图的出口，改共享值从「1 次」变「N 页各 1 次」；
  `shared_pool` 还在（内部同样是 `exportConfig`），只是改不了。
- `project_import` 删了 → MCP 侧**建不了工程**：它比 `openProject` 多两件事
  （指定输出工程名、覆盖已有工程）；openProject 遇到已存在的工程目录会直接接着用，不会重新导入。
  退化路径只有 `project_new` + 逐页 `page_overwrite`（`overwritePage` 在 pageId 不存在时是追加，能堆出来）。
- 还有设计约束：项目原则是「命令面 = MCP 工具面 = core 能力面」，
  只删 MCP 侧会破坏这条等式，要么都删要么都留。

### 改了什么（纯文案）
- `mcp/src/index.ts`：三个工具描述重写（project_new 明确说是目录工程；project_import 点明「与打开工程不同」；
  project_export 点明是去重视图、工程本体不受影响）；6 步闭环 instructions 补「工程形态」一句。
- `cli/src/index.ts`：`init` / `import` / `export` 三条命令的 description 同步改。
- `docs/implementation-design.md`：新增 **§5.1 术语：打开工程 vs project_import**（含写回约定），
  §5 对照表与 §8 时序图标注，§7 工作流建议补 project_new、page_overwrite 追加语义。
- `README.md`：MCP 段落加「术语区分」三条。

验证：typecheck 5/5，core 40 / cli 28 / mcp 15 全过；
用 `createServer()._registeredTools` 实际读出工具描述确认拼接无多余空格。
