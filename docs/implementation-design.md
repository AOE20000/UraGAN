## 1. 现在能做什么（当前能力）

**一句话：把一段需求变成一条视频。** 核心操作三步——选页面、填文案、导出视频；三个入口共享同一套核心引擎，行为完全一致。

### 1.1 三种使用方式（命令面 = 工具面 = 能力面）

| 方式 | 适合谁 | 能做什么 |
|---|---|---|
| **TUI**（终端交互，`uragan tui`） | 直接在电脑上操作的人 | 浏览/排序页面、编辑文案字段、内置文件管理器打开工程、一键渲染 |
| **CLI**（命令行） | 脚本、批处理、自动化 | 建工程、导入/导出配置、页面排序、文案框架、渲染、校验 |
| **MCP**（AI 对话，`uragan serve-mcp`） | 想"说人话"做视频的人 | 15 个工具，Agent 自主走完六步闭环 |

一致性规则：**CLI 命令面 = MCP 工具面 = core 能力面**，不会出现"界面能做、命令做不了"的差异；TUI 里改了未保存的内容，CLI/MCP 立刻读得到。

### 1.2 六步工作流（全部已实现、可自动化）

```
① 生成配置 → ② 导入展开 → ③ 选择排序 → ④ 导出文案框架 → ⑤ 导入填充 → ⑥ 渲染视频
```

另有两条迭代循环：**单页循环**（`page get` 抽出单页 → AI 改 → `page overwrite` 覆盖）与**整体设计循环**（`project_export` 导出共享池去重视图 → 改 → `project_import` 重新展开）。

### 1.3 工程形态与「打开即导入」语义

| 形态 | 说明 |
|---|---|
| `.uragan` 单文件 | 整个工程一个纯 JSON 文本文件，人可读、AI 可读写、程序可解析；素材只存引用不入包 |
| `.uragan/` 目录工程 | 每页一个独立文件 + `project.json` 内部清单（播放顺序、页组），便于版本管理与逐页协作 |
| `.uragan.work/` 工作目录 | 打开 `.uragan` 一律按导入处理：工程在工作目录里进行，原文件保留为**持久存储**，`Ctrl+S` 才导出回去 |

### 1.4 分发形态（Windows，全部可用）

- **目录便携包**（`pnpm run pack`）：全量约 600MB（含渲染引擎与离线浏览器）/ 精简版 / 一键安装脚本。
- **单文件 exe**（`pnpm run pack:exe`）：约 86MB，**目标机器无需安装 Node**，双击即进 TUI；`serve-mcp` 子命令直接当 MCP Server 用。

### 1.5 边界（诚实说明）

- **单文件 exe 为精简版**：不含 Remotion 渲染引擎（依赖原生绑定，无法随 SEA 单文件携带）；执行 `render` / `assets check` 会给出明确提示，改用目录便携包即可。
- 页面模板目前 **4 类**（开头 hero / 分节 section / 卡片 grid / 数据 chart），输出 mp4（h264/h265/vp8/vp9）。
- 工程能力 106 项自动化测试全部通过（core 40 / render 10 / mcp 15 / cli 41）。

## 2. 特性清单

### 2.1 工程与数据

- **单文件 / 目录 / 工作目录三形态**互通：导入拆分、导出合并；独立文件（单页）可当整体文件用。
- **交换配置 `.json/.jsonc`**：与 AI 交换的中间形态，支持注释；导入展开、导出去重合并。
- **去重与冲突自动化解**：导出时相同定义自动合并进共享池；同名异值自动重命名（如 `color_primary_p02_feature`），键名永不冲突、绝不报错中断。
- **页面物理隔离**：导入时共享定义深拷贝进每页 `$defs`，改一页绝不影响其他页；本地引用不变量由解析器强制（禁止跨页引用）。
- **页组锁定**：整体文件移入工程时内部页序锁定成组，重排时整组跟随；导入拆分出的页面不成组，可自由移动。
- **素材只存引用**：图片/字体一律存 `http(s)` 或相对路径引用，工程文件永远纯文本可读；离线资产放工程旁的 `assets/` 目录即可。

### 2.2 编辑体验（TUI）

- **6 个视图**：页面 / 共享池 / 组件 / 资产 / 信息 / 日志，`1-6` 一键切换；列表超出可视高度自动隐藏并提示「上方/下方还有 N 项」。
- **中文输入友好**：IME 整词直接上屏、左右方向键移动光标、退格删除。
- **内置文件管理器**（`O`）：路径提示栏显示当前位置（长路径保留末尾）；`/` 输入绝对路径直达；`H` 一键回主目录；展示目录内全部文件、可开工程打标；位置自动记忆；起始目录智能选择（工程产出目录 → 记忆位置 → 当前目录，落在程序自身目录时回退主目录）。
- **单页导入/导出**：任选一页导出成独立文件（`G`），改完放进工程目录自动吸收（`U`）。
- **页组锁定排序**、**操作日志留痕**（打开/保存/校验/渲染等）。

### 2.3 内容管线

- **文案框架双形态**：同一份框架同时输出 JSON（程序/AI 权威）与 Markdown 表单（普通用户直接填表；多行/含符号内容走 `f@编号` 围栏块，原样往返零转义）。
- **组件系统**：全局组件统一维护，需要时一键「复制代码到页面」内联后自由定制（定义冲突沿用自动改名规则）。
- **校验与资产体检**：三段校验（结构/引用/语义）输出双格式报告（JSON 供 MCP、文本供人）；`assets check` 渲染前暴露失效引用（网络不可达/路径缺失/字体缺失）。

### 2.4 渲染

- 4 类页面模板翻译为 React/Remotion 合成，逐帧精确控制；时长由页动画边界推导，可被工程/页级覆盖。
- **内置 Chrome Headless Shell（约 270MB）**：离线渲染可用；缺失时自动在线下载，也可用 `URA_CHROME_BROWSER` 指定浏览器。
- 支持 h264/h265/vp8/vp9 编码与进度输出。

### 2.5 AI 集成（MCP）

- **15 个工具**：`project_new / project_import / project_export / project_validate / list_pages / reorder_pages / page_get / page_overwrite / copy_export / copy_import / shared_pool / component_list / component_inline / assets_check / render_video`。
- **对话式闭环**：Agent 按「建工程 → 排页面 → 导框架 → 收文案 → 渲染」自主走完六步；已实测接入 TRAE，Claude 等支持 MCP 的客户端同样可用。

### 2.6 工程质量

- 全仓 106 项自动化测试：往返不变量、冲突重命名幂等、本地引用拦截、校验快照、CLI 端到端、MCP 契约、TUI 交互回归（视图/文件管理器/持久文件工作流/溢出提示）。
- 类型严格（TypeScript strict）、五包共享领域类型与 zod schema。

## 3. 设计要点（为什么这样设计——只讲原则）

### 3.1 三个顶层不变量（不可违背）

1. **本地引用不变量**：任意页面内容只允许引用本页 `$defs`（或内建定义），**禁止跨页引用**——页面物理隔离的代码级保证，解析器强制执行。
2. **往返不变量**：`导出整体配置 → 导入展开` 与 `导入整体配置 → 导出交换配置` 均为一轮不变式（页内容逐字节一致、定义键值一致）。
3. **键唯一不变量**：导出产物中任意定义键全局唯一；冲突由系统自动重命名，绝不报错中断。

### 3.2 关键语义决策

- **`$shared` 是汇总投影，不是数据源**：数据源永远是各页自己的 `$defs`；导出整体配置时重新去重投影生成 `$shared`。单页编辑永远不需要"找共享池算账"。
- **播放顺序唯一权威 = `pages` 数组顺序**（页内不存 order，避免双写冲突）。
- **占位符/动画一律用 `cid` 寻址，绝不用数组下标**（下标在 AI 编辑后会漂移）。
- **单文件工程 = 交换配置的展开形**：同一份文本格式，人、AI、程序三方同用，不打包、不压缩、无二进制。
- **素材不入包**：只存引用，渲染时才解析（下载/相对路径/系统字体兜底）。

### 3.3 仓库结构

```
packages/
├── shared/    # 领域类型、zod schema、常量（被 core/cli/mcp/render 复用）
├── core/      # 逻辑引擎（唯一持有状态与规则）：parser / expander / dedup / copy / inline / validate / store
├── cli/       # 命令行 + TUI（commander + Ink，含内置文件管理器）
├── mcp/       # MCP Server（stdio，工具面 = CLI 命令面）
└── render/    # Remotion 翻译与合成（内置离线浏览器 vendor/）
scripts/       # 打包脚本（package-portable.mjs 目录包 / package-exe.mjs 单文件 SEA）
```

## 4. 未来计划（接下来做什么）

### 4.1 近期（规划中）

| 方向 | 说明 |
|---|---|
| **渲染进单文件 exe** | 当前 `uragan.exe` 为精简版（不含 Remotion）；目标是单文件也能直接出片 |
| **更多页面模板与转场/动效** | 现有 hero/section/grid/chart 四类；扩展更多版式与页间转场 |
| **原生 GUI** | 面向不习惯终端的用户：可视化编辑、拖拽排序、预览。预留 `uragan gui` 入口，框架选型待定（不提供浏览器形态） |
| **消除 SmartScreen 提示** | 为 exe 配置代码签名证书，让分发更顺滑 |

### 4.2 远期（v1.1+ 开放项）

- **页间转场**：`transitions` 表（fade/slide 等）vs 当前页级 out 动画兼作转场。
- **音频**：背景音乐 / 配音 / 字幕轨。
- **文案变量**：数字高亮、`{{brand}}` 类名称变量模板。
- **异步长任务**：渲染改拉模式（`render_status`），支持超长视频。
- **schemaVersion 迁移器**：保证旧版工程文件自动升级。
- **模板与素材共享**：页面模板、动画效果、文案框架的分享与复用（本地目录或市场形态）。
- **多端与协作**：多人 / 多 AI 在同一工程上协作、更细粒度的变更合并。
